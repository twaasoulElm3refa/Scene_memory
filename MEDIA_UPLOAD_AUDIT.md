# Scemory media upload audit

Audited 2026-11-02. API paths below are under `/api/v1` unless shown otherwise. `events_images` is the existing marketplace media table; `cloudinary_media_assets` is the additive Cloudinary metadata table. No historical files are migrated by this change.

| Flow | Entry and owner check | Processing, fields and delivery | Storage after integration |
| --- | --- | --- | --- |
| User and historical event creation | `POST /events/create/user`, `/events/historic/user`, `/create`, `/user-dshboard/create/Event`; `EventUserCreateController`, `EventsRequest`, Sanctum, event owner assigned server-side | `ProcessEventImageJob` / `ProcessEventVideoJob`; `events_images.full_url`, `preview_url`, disk and metadata fields; `single_event.vue`, creator/user event views | New image clean originals: authenticated Cloudinary plus private local temporary copy; blurred/watermarked image preview: private `media`, served by Laravel after publication check. Videos: original private local, published trailer may be Cloudinary. |
| Admin event creation | `POST /events/create`, `/events/historic`; `EventAdminCreateController`, admin middleware | Same jobs and DB fields as user creation | Same image original/preview split and unchanged video flow |
| Add event media and media requests | `POST /user-dshboard/{slug}`, `/media-request/upload/{id}`; `EventAccess` in `UserDashboardController` / `MediaRequestController` | `EventMediaIngest`, video job; `events_images`; `single_event.vue`, user dashboard | New images use authenticated Cloudinary originals immediately, independently of approval. Image previews stay local. Video trailers retain existing approval promotion. |
| Admin add event image or video | `POST /event-images/create/{id}`; admin middleware | `EventImageController` → `EventMediaIngest`; `events_images`; admin event views | Same split |
| Event preview, card thumbnail, playback | `GET /media/{media}/preview`, `/thumbnail`; publication check and signed reviewer URL in `MediaDeliveryController` | `EventsImges::toArray`, `MediaAccessService`, `MediaThumbnailService`; `single_event.vue`, `DiscoveryMediaCard.vue`, download view | Newly processed image previews and thumbnails stream from local pixels through Laravel; existing Cloudinary previews remain supported for legacy records. Video trailer CDN/poster behavior is unchanged. |
| Paid original and download | `/download/{media}` and signed purchased original route; `DownloadController`, `MediaAccessService::canDownload` checks owner/admin or `entitlements` | `events_images.full_url`; `download.vue` | New authenticated Cloudinary originals are fetched server-side with short-lived private-download URLs and proxied with no-store headers. Retained private local fallback handles outages. Legacy local images and videos keep their prior endpoint. |
| Event media and event deletion | `/event-images/{id}/delete`, `/user-dshboard/{id}/delete`, event/admin deletion routes; ownership/admin checks and purchased-media guard | Related `events_images`, purchase/entitlement relationships | Deletion is blocked when a purchase entitlement exists. Existing public Cloudinary previews are purged on deletion; authenticated originals and private temporary copies are retained for operator reconciliation after record deletion. |
| Comments | `POST /comments/{id}/create`, `DELETE /comments/{id}/delete`; authenticated, author/admin deletion | `CommentController`, `CommentRequest`, `comment_images.path/disk`, `CommentImage::url`; `single_event.vue`, comments views | Public Cloudinary images when enabled, local public fallback; deletion through unified service |
| Category and subcategory images | `POST /categories/create`, `/categories/edit/{id}/update/edit`, `/sub_categories/create`, `/sub_categories/update/{id}`; admin middleware | `CategoriesCreateController`, `CategoryController`, `SubCategoriesCreateController`, `SubCategoryController`; `categories.image`, `sub_categoreys.image`; admin and directory Vue views | Cloudinary image reference or legacy public path |
| Country images | `POST /countries/create`, `/countries/{id}/update`; admin middleware | `CountriesCreateController`, `CountriesController`; `countries.image`; country Vue views | Cloudinary image reference or legacy public path |
| Event cover image | `POST /events/{id}/update`, `/user-dshboard/{slug}/update/Event`; admin or owner | `EventAdminController`, `UserDashboardController`; `events.image`; event directory/admin Vue | Cloudinary image reference or legacy public path |
| Footer logo | `POST /footer/update`; admin middleware | `FooterController`; `footers.logo`; footer settings Vue | Cloudinary image reference or legacy public path; replacement deletes prior asset after DB update |
| Virtual gift catalog image | `POST /v1/admin/gifts/catalog[/{id}]`; admin middleware | `VirtualGiftAdminController`, `virtual_gifts.image_path`, `VirtualGift::image_url`; gift views | Cloudinary image reference or legacy public path; historical gift snapshots retain their image URL |
| Image tag and media analysis input | `POST /tools/image-tags`, media validation API; authenticated/rate limited | `GenerateImageTagsService`, `ImageDataUrlFactory`, `SafeMedia`, `VideoFrameExtractor` | Analysis input only; no new persistent asset |
| Dormant legacy creation method | `HomeController::create` has no current route | Now delegates to `EventMediaIngest` if reused | No public paid original upload |

No avatar upload endpoint or message attachment flow was found. User avatar fields are read and user data deletion removes stored images; existing avatar values remain supported. Static assets under `public/images` are application assets, not user uploads.

Authorization follows the existing route middleware and `EventAccess` checks. Public CDN paths are used only for already publishable catalog images and video trailers. Existing `original_disk` / `preview_disk` distinguish legacy and new media. The image flag controls new authenticated original uploads; the video flag remains independent.
